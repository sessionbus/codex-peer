# codex-peer v0.5.9

This release requires Sessionbus v0.5.9 (daemon and hub) and pins the Sessionbus Go SDK `v0.5.9`. The version matches core v0.5.9.

**Breaking, a flag day.** The unreleased lane policy field `idle_message` is removed from the protocol and the SDK; message wake is mandatory. This peer requires a v0.5.9 daemon. Peers built with SDK v0.5.7 or earlier are incompatible with it. Upgrade the hub, the host daemons and the product integrations together. Follow the upgrade steps, including the offline lane-row edit, in the [core v0.5.8 release notes](https://github.com/sessionbus/sessionbus/releases/tag/v0.5.8). v0.5.9 has the same runtime as v0.5.8.

Fixes:
- **Typed argument conflicts are rejected before launch.** A typed lane `model` or `reasoning_effort` combined with a raw native argument that selects the same setting (for example `model` plus `--model`) now fails spawn with `argument conflicts with typed field <name>`. Before this, it reached `codex app-server` and failed late. Untyped native arguments are unchanged, and parsing stops at `--`.
- **`codex-peer --native-version` runs native Codex directly.** It no longer starts a broker or App Server, and creates no launch directory. The exec strips all `SESSIONBUS_*` variables.

`scripts/install-codex.sh` installs the latest release by default, so it now installs v0.5.9. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window. The legacy per-product installers inherited from the combined repository (`scripts/install-{claude,grok,qwen,opencode,kilo,pi,omp}.sh`) are removed. They installed the combined v0.5.3 peers, which are incompatible with Sessionbus v0.5.8 and later. Use each product repository's installer. The historical combined releases and assets remain available.
