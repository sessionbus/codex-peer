# codex-peer v0.5.16

## SDK 0.5.16 refusal clarification

The Go SDK is pinned directly at v0.5.16. Shared support stays at the actual reviewed common commit `29ddcb4585deaffc637163381ea1bce4a312e237`; the direct SDK requirement selects v0.5.16 over that common revision's older minimum. No product hello, filesystem, cwd, permission or lifecycle mechanism is added.

The SDK reports `unknown_transfer` for a missing local transfer binding and for an ended binding after its existing earlier checks. Existing path, field, role and overwrite checks keep their current precedence and conflict refusals. On a local daemon upgraded to Sessionbus v0.5.16, the SDK's existing hello paths opt in to `unknown_transfer` (-32020) for a status request with no accessible live transfer, including an absent or ended ID. An older daemon keeps `transfer_failed` (-32019); the SDK accepts that legacy answer too. An old daemon can expose the extra hello info key as ordinary public metadata.

The new wire answer applies only to local status replies. Wire Accept/Cancel and federation keep their existing answers. Status still does not return or preserve a completed outcome, file hash or terminal history. A missing final notice does not prove failure or make replay safe. Files are still read and written directly as the OS user, with no sandbox or native approval per path. Tightening transfer permissions later remains OPEN and is not a release gate.
